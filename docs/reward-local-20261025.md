# 文章与视频打赏（本地预览）

运行 `node scripts/preview-reward.cjs`，打开：

http://127.0.0.1:8000/article.html?slug=reward-preview&preview=reward#rewardTitle

此预览地址由本地服务器注入测试文章和本地统计方法，不会发布测试文章。其他页面仍按现有逻辑读取内容。

## 功能

- 文章、视频详情页正文后提供打赏卡片。
- 文案：如果这篇文章/视频对你有帮助，请我喝杯瑞幸吧。
- 预设 1、5、10 元，默认 5 元；自选 0.01–200 元，精确到分。
- 点击按钮同步打开独立支付窗口；被浏览器拦截时提供新标签页链接。部分移动浏览器会自行将弹窗显示为标签页。
- 支付窗口支持微信/支付宝切换、保存二维码、关闭窗口；直接访问时同样校验金额。
- 二维码从用户原图识别支付内容后重新生成，逐一验证内容相同。网站只保存新码，不保存含姓名的原图。

## 支付边界

当前是个人静态收款码。所选金额仅作为扫码支付提示，用户需要在支付 App 中手动输入；页面的 200 元上限无法限制支付 App 中实际输入的金额。未接入支付订单、金额锁定或到账回调，也不会显示未经验证的支付成功状态。

姓名已从网站二维码素材中移除。付款 App 根据账户展示的收款人信息由支付平台决定，网站无法控制。

## 验证

先启动本地预览服务器，再执行 `node scripts/check-reward.cjs`。浏览器检查使用本地测试数据并拦截远程请求，覆盖金额范围和精度、独立窗口、支付方式切换、二维码下载、关闭返回、窗口拦截、文章与视频入口，以及 320/390/1440 像素布局。二维码支付内容已用本地识别工具与原图比对一致。

本地开发阶段未执行推送或部署；同步到 GitHub 后的上线状态以部署工作流结果为准。

## 居中修复与自动填金额调研

独立窗口现在按当前显示器可用区域居中，缺少屏幕原点信息时按博客所在浏览器窗口居中。小屏幕会缩小支付窗口；复用已有窗口时再次移动到中心，并计算浏览器边框尺寸。手机或限制弹窗的浏览器仍可能显示为标签页或自行调整位置。

执行 `node scripts/check-reward-position.cjs` 可回归主屏、负坐标副屏、小屏幕、缺少显示器原点信息以及复用窗口的位置计算。此检查使用模拟屏幕参数，实际窗口位置仍受浏览器管理。

用户确认目前只有两张个人收款码。尚未接入自动填入金额；不能将页面提示的金额当成已经锁定的支付金额。

调研参考：

- [GoFrame 捐赠页源码](https://github.com/gogf/gf-site/blob/main/docs/community/%E6%94%AF%E6%8C%81%E6%88%91%E4%BB%AC/%E6%9D%A5%E6%9D%AF%E5%92%96%E5%95%A1.md)：直接展示微信/支付宝收款图片。
- [腾讯云微信 Native 支付示例](https://docs.cloudbase.net/integration/wechat-pay-native)：服务器提交含金额的订单，取得订单二维码；需要商户号、关联 AppID 和签名凭证。
- [支付宝交易预创建接口](https://developer.alibaba.com/docs/api.htm?apiId=862&docType=4)：提交 `total_amount` 创建订单，返回订单二维码 `qr_code`，需要应用与签名配置。
- [浏览器窗口打开 API](https://developer.mozilla.org/en-US/docs/Web/API/Window/open)：位置、尺寸最终可能由浏览器修正。
