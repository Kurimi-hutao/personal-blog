## 发布与站长平台手动步骤

1. 将修改同步到实际 GitHub 仓库。保留原 `TCB_ENV_ID`、`TCB_SECRET_ID`、`TCB_SECRET_KEY` Secrets；从干净 checkout 执行 `npm run test:seo` 和既有部署工作流。不要直接上传根目录或旧 `_deploy`，新的 sitemap 和详情在构建输出中生成。
2. CloudBase 网关/静态托管：不存在路径返回 **404**，错误页指向 `/404.html`，不要把所有路径重写成首页并返回 200。撤稿路径应返回 410 或 404；移除下线页面后刷新 CDN。验证主页 200、新详情 200、不存在页 404、管理页有 noindex。若控制台路由不支持响应状态，需要在现有网关配置错误状态处理，不能由静态 HTML 伪造。
3. [百度搜索资源平台](https://ziyuan.baidu.com/)：添加 `https://joestarzhang.cn`，按平台提示完成 DNS、文件或 HTML 标签认证。DNS 不依赖构建最方便；若使用验证文件，确保每次构建保留根目录文件。普通收录/API 提交界面取得 token，存为 GitHub Secret `BAIDU_PUSH_TOKEN`；以平台提供的站点名称、接口权限和配额为准。若账号没有 sitemap 提交入口，不承诺能开通。
4. [Bing Webmaster Tools](https://www.bing.com/webmasters/)：添加域名并完成 DNS/文件认证，提交 `https://joestarzhang.cn/sitemap.xml`。生成 8–128 位字母数字/短横线组成的随机 `INDEXNOW_KEY`，放入 GitHub Secrets。构建会生成同名 `.txt` 验证文件；该文件按协议必须公开，**它不是百度 token 或服务端账户凭据**。没有把推送逻辑或百度 token 放进前端。IndexNow 200 仅代表接收，202 等待验证会保留重试，不当作已收录。[协议依据](https://www.indexnow.org/documentation)
5. 可选 [Google Search Console](https://search.google.com/search-console/) 域名属性 DNS 认证，提交同一 sitemap，抽检正文和 canonical。[JavaScript 抓取依据](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
6. 发布内容后：可立即手动运行工作流；自动路径由可信服务端在数据库事务提交后发送 GitHub `repository_dispatch`，事件名 `content-published`。GitHub App/PAT 必须存服务端 Secret/Vault，不能放 admin.js。生产 webhook 需要鉴权、仅允许站长内容变更、对请求去重并限制速率；当前没有新建未认证的公网 webhook。每小时定时构建兜底处理发布、编辑、预约到期和撤稿；Actions 排队可能延迟，不保证整点或即时。构建失败保留上一版本，搜索推送失败不回滚已部署网站，可重跑。
7. 建议关注 GitHub Actions 失败通知；搜索接收记录存 `.seo-submit` 缓存，仅成功接收批次写入。缓存被清理可能重复通知，服务端去重不等于搜索引擎必然收录；不记录敏感请求 URL 或密钥。

## 访问统计开通与口径

按你的选择，暂时只完成可配置接入，未开通服务或付费订阅。创建 Plausible 站点（托管或兼容自建），域名填 `joestarzhang.cn`，时区选 Asia/Shanghai；复制控制台生成的公开 HTTPS 脚本地址，设置 GitHub Variable `PLAUSIBLE_SCRIPT_URL` 后重新部署。使用支持 `plausible.init` 的当前脚本；不要粘贴整段 script 标签、API key 或密码。验证后台能看到自己的测试访问后，在服务端排除内部测试流量。

- UV：Plausible 当日去重访客估算，不是实名人数、跨天唯一人数。
- 会话：连续活动，30 分钟无活动结束；PV：页面浏览事件。三个指标不能互换。
- 搜索来源：按 referrer 的搜索引擎来源分组；缺失来源是 direct/unknown，不能全部归为自然搜索。关键词数据主要来自认证后的站长平台，不虚构访问者搜索词。
- 爬虫：Plausible 过滤已知机器人，不执行 JS 的爬虫不会出现在浏览器统计里；CloudBase/CDN 请求日志应另作“机器人/疑似机器人/其他请求”报表。UA 可以伪造，认定 Google/Bing 官方爬虫须按其公开方法验证 IP，不能把所有含 bot 的 UA 当作已验证爬虫。不要把 HTTP 请求数计作人的会话/PV。
- 现有 `view_count`、点赞和播放计数保留为业务互动数据，不作为真实 UV/会话；不把历史计数转换成新统计历史。
- 不上传搜索框内容、评论、邮箱、登录 ID；新接入不使用 localStorage 生成用户标识。原站的书签/签到等本地业务存储保持不变。网关日志建议短期保留、限制访问，不把原始 IP 明细公开。
