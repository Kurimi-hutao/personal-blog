# 手机布局与点击动效优化（2026-10-15）

## 复现的问题

- 首页同时由公共动效和首页脚本处理 pointerdown，一次轻点会产生两组水墨波纹。
- 触摸开始就播放特效，滑动与长按也会触发。
- 320px 与 844px 横屏下，文章目录和返回顶部按钮的矩形相交。
- 将手机可用视口缩至 390×430 后，搜索弹窗内部高度超过容器，结果区域被裁掉。
- 手机与低功耗设备的保护逻辑直接跳过花瓣创建，手动“唤一场桃花”也没有反馈。

## 修改

- 公共模块统一处理点击反馈。触屏只在 10px 内、500ms 内完成的轻点后播放；拖动、长按、输入控件、禁用按钮及弹窗内部不生成全局粒子。最多同时存在四组波纹，自动清理节点，移除波纹动画中的 blur。
- 手机主动召唤花瓣改用现有 WebP 素材与 transform / opacity 动画，每次最多八片，低功耗设备最多五片，完成或切换到后台后清理。减少动态效果模式只显示静态提示。
- 手机导航采用双列入口，横屏采用四列；底部增加收起按钮。菜单打开时正文不可交互，键盘焦点保持在导航区域，打开搜索会先关闭导航。
- 目录加入底部横向工具栏，避开主题和返回顶部按钮。阅读正文期间保持可用，弹窗、导航或键盘打开时隐藏工具栏；其他页面继续随滚动方向收起。
- 搜索弹窗按 VisualViewport 可用高度布局，头部与搜索框固定，结果区独立滚动。快捷入口横向滚动，收藏优先可见，搜索结果标题最多两行。
- 文章、视频与作品列表的手机场景横幅收紧，保留现有水墨图，让筛选和内容更早出现。
- 大图关闭按钮为 44×44，放进弹窗边界，横屏也能触达；评论附件删除与阅读按钮保持至少 44px 的触控尺寸。
- 更新相关文件版本与 Service Worker 缓存版本。

## 验证

先运行 `python -m http.server 8015 --bind 127.0.0.1`，再运行：

- `node scripts/check-mobile-motion.cjs`：320×568、375×812、390×844、430×932、844×390；真实触摸事件模拟轻点、滑动与长按，验证单次波纹、粒子清理、手机花瓣反馈、导航、键盘占屏后的搜索、目录触达、工具栏不重叠、画廊关闭、小屋及各主页面布局。另检查减少动态效果模式和桌面点击。
- `node scripts/check-p1-features.cjs`：评论、草稿、附件、续读、目录和收藏回归。
- `node scripts/check-blog-refinements.cjs`：搜索、类型筛选、缓存与重试回归。
- `node scripts/check-loading.cjs`：加载层、字体失败、小屋日夜资源、缓存和离线导航回归。

浏览器使用合成内容，写请求被拦截或在本地模拟；不修改线上留言。截图与检查结果位于 `outputs/mobile-motion/`。

目前无需补充素材。真实手机的键盘、刘海安全区与低端设备帧率仍需真机复核；本轮使用浏览器触屏和视口模拟，不宣称已完成真机或帧率测试。
